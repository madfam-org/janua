# Passkeys & WebAuthn Authentication

Implement passwordless authentication using passkeys (WebAuthn/FIDO2) for enhanced security and user experience.

## Overview

Passkeys provide a phishing-resistant, passwordless authentication method using biometrics, security keys, or device credentials. Built on WebAuthn/FIDO2 standards, passkeys offer strong security while simplifying the user experience.

## Benefits

- **Phishing Resistant**: Cryptographically bound to specific origins
- **No Passwords**: Eliminate password-related vulnerabilities
- **Better UX**: One-touch authentication with biometrics
- **Any authenticator**: Built-in authenticators (Touch ID, Windows Hello, Android) and roaming ones (security keys, a phone) can both register
- **Strong Security**: Public key cryptography with hardware backing

## Quick Start

The TypeScript SDK runs the whole ceremony for you: it fetches the options, decodes them, calls the browser's WebAuthn API, encodes the result and verifies it with the API.

### 1. Register a Passkey

The user must be signed in.

```typescript
import { createClient } from '@janua/typescript-sdk'

const client = createClient({ baseURL: 'https://api.janua.dev' })

// Fetches the options, calls navigator.credentials.create() and verifies
// the new credential with the API
await client.registerPasskey('My Laptop')
```

### 2. Sign In with a Passkey

```typescript
// With an email, the browser offers that user's passkeys; without one, it
// offers any discoverable passkey for this site
const { user, tokens } = await client.signInWithPasskey('user@example.com')

console.log('Authenticated as:', user.email)
```

A passkey sign-in creates an ordinary Janua session. Signing out, revoking the session or resetting the password revokes it like any other.

## React Implementation

```tsx
'use client'

import { useEffect, useState } from 'react'
import { checkWebAuthnSupport } from '@janua/typescript-sdk'
import { client } from '@/lib/janua'

export function PasskeyLogin() {
  const [isSupported, setIsSupported] = useState(false)
  const [isLoading, setIsLoading] = useState(false)

  useEffect(() => {
    setIsSupported(checkWebAuthnSupport().available)
  }, [])

  const handlePasskeyLogin = async () => {
    setIsLoading(true)
    try {
      await client.signInWithPasskey()
      window.location.href = '/dashboard'
    } catch (error) {
      console.error('Passkey authentication failed:', error)
    } finally {
      setIsLoading(false)
    }
  }

  if (!isSupported) {
    return null
  }

  return (
    <button
      onClick={handlePasskeyLogin}
      disabled={isLoading}
      className="w-full flex items-center justify-center gap-2 px-4 py-2 border border-gray-300 rounded-md hover:bg-gray-50"
    >
      {isLoading ? 'Authenticating...' : 'Sign in with Passkey'}
    </button>
  )
}
```

## Encoding: base64url, not base64

The API sends every binary WebAuthn value (the challenge, the user id, credential ids) as **base64url**: `-` and `_` instead of `+` and `/`, and no padding. The browser's `atob` accepts only standard base64 and throws on `-` or `_`, which a random challenge contains most of the time. If you build the ceremony yourself, convert with the SDK's helpers:

```typescript
import { base64UrlToArrayBuffer, arrayBufferToBase64Url } from '@janua/typescript-sdk'

const challenge = base64UrlToArrayBuffer(options.challenge)   // for navigator.credentials
const rawId = arrayBufferToBase64Url(credential.rawId)          // back to the API
```

`WebAuthnHelper`, `client.registerPasskey` and `client.signInWithPasskey` already do this.

## API Reference

All routes are under `/api/v1/passkeys`.

### POST /api/v1/passkeys/register/options

Start passkey registration. Requires `Authorization: Bearer <access_token>`.

**Request** (all fields optional):
```json
{
  "authenticator_attachment": "platform"
}
```

Omit `authenticator_attachment` to allow every kind of authenticator (recommended). Send `"platform"` or `"cross-platform"` only to restrict it.

**Response** (WebAuthn `PublicKeyCredentialCreationOptions` in JSON form; binary values are base64url):
```json
{
  "challenge": "base64url-challenge",
  "rp": { "name": "Janua", "id": "example.com" },
  "user": { "id": "base64url-user-id", "name": "user@example.com", "displayName": "User" },
  "pubKeyCredParams": [
    { "type": "public-key", "alg": -8 },
    { "type": "public-key", "alg": -7 },
    { "type": "public-key", "alg": -257 }
  ],
  "timeout": 60000,
  "excludeCredentials": [],
  "authenticatorSelection": {
    "residentKey": "discouraged",
    "requireResidentKey": false,
    "userVerification": "preferred"
  },
  "attestation": "none"
}
```

The challenge is valid for 5 minutes.

### POST /api/v1/passkeys/register/verify

Complete registration. Requires `Authorization: Bearer <access_token>`. Body: `{ "credential": <the browser's credential in JSON form>, "name": "My Laptop" }`.

### POST /api/v1/passkeys/authenticate/options

Start a passkey sign-in. Body: `{ "email": "user@example.com" }` or `{}`. The response carries `sessionId`, `challenge`, `rpId`, `timeout`, `allowCredentials` and `userVerification`. The challenge is valid for 10 minutes.

### POST /api/v1/passkeys/authenticate/verify?session_id=&lt;sessionId&gt;

Complete the sign-in. Pass the `sessionId` from the options call as the `session_id` query parameter; the server reads the challenge by it and never accepts a challenge from the client. Body: `{ "credential": <the browser's assertion in JSON form> }`. The response carries `access_token`, `refresh_token`, `token_type`, `expires_in` and `user`.

### Errors

| Status | Meaning |
|--------|---------|
| `400` | The challenge expired or was already used, or verification failed |
| `404` | The credential is not registered |
| `503` + `Retry-After` | Janua could not store or read the challenge; retry after the indicated seconds |

## Security Considerations

1. **HTTPS Required**: WebAuthn only works over HTTPS
2. **Origin Binding**: Credentials are bound to the registering origin
3. **One-time challenges**: Each challenge is consumed once, whichever server instance receives the verification
4. **Fallback Methods**: Always provide alternative authentication methods
